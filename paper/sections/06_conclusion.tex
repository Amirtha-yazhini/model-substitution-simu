\section{Limitations and Conclusion}\label{sec:conclusion}

\textbf{Limitations.} Five matter most.
(i)~\emph{The main comparison uses simulated models.} Calibration, the honest test sessions, the
main comparison, the cheating-rate sweep and the load-balancing comparison all use SHIM's simulator.
The fitted pair takes its answers and speeds from real measurements, but its writing habits and
accuracy are still hand-written, and the IRIS-lite check shows this can move $\epsilon^*$. The
coverage, recorded-response and live results come from real endpoints; the detection rates in the
main comparison describe the simulator.
(ii)~\emph{One real session per endpoint.} Free quotas allowed one 240-request session per endpoint,
so thresholds could not be set on real traffic, and the real-endpoint results use permutation
p-values instead of the fixed thresholds.
(iii)~\emph{Simplified rebuilds.} None of the auditors is the authors' code. OTE uses 8 of 40
questions, IRIS-lite 16 of 179 features, KBF and BENCH 15 and 12 items, and GATEOPS leaves out
GateScope's memory test. Each result is a lower bound on what the original method can do.
(iv)~\emph{Free endpoints, at one point in time.} Groq served nearly all real traffic; other
providers asked for payment or ran out of daily quota. Free tiers change every month.
(v)~\emph{Simulated cheaters and a small live test.} A5 is our own design; a real one could be better
or worse. The live test used 96 requests per arm on one provider, and honest load balancing could
not be tested live.

\textbf{Conclusion.} We tested five published auditors and one new combined auditor against the same
cheating gateway, with every threshold fixed before testing. Auditing is cheap: a session costs well
under a cent. But it is not robust. A gateway that recognises test-shaped requests beats every
auditor, and the shape it recognises is exactly what makes the tests cheap. Below a cheating rate of
about 10--15\%, no audit can catch the gateway without too many false alarms. And timing-based
auditors flag honest load balancing more readily than fraud. A wrong model can be caught from the
text; undisclosed routing and a wrong bill cannot. Trustworthy billing for LLM APIs will need test
requests that look like normal traffic, gateways that disclose their routing, and metering the
customer can verify. Black-box testing alone cannot provide the last two.
